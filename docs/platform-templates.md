# 招聘平台模板适配

招聘站点首先按本地模板识别页面结构，再沿用按页面顺序的读取、匹配、填写和整页读回流程。模板只描述控件与记录结构，不存储申请人的值。

| 平台 | 启用模板的依据 | 本轮处理范围 |
| --- | --- | --- |
| Moka | apply-block / apply-fields / apply-field 组件组合；支持企业自有域名及变化的 CSS 后缀 | 字段标签、同组经历序号、分离年月、经历添加、学校/专业远程搜索、固定选项菜单 |
| Hotjob | form-cell / form-cell-inner / tit-wrap 组件组合 | 章节和重复记录边界；保留现有文本、单选、下拉与已填页面学习能力 |
| 北森 | form / form-item 与 Phoenix 控件组合 | 重复记录边界；保留现有单选弹窗、地区与日历确认/读回能力 |
| 飞书招聘 | 当前仅有域名提示，尚无经过验证的 DOM 契约 | 使用通用解析，专用模板待真实表单样本验证 |
| 其它或结构冲突 | 无唯一完整组件特征 | 使用通用解析 |

只知道域名不能启用模板；域名和组件结构冲突、同时出现多个平台的完整特征时也退回通用解析。模板修订号写入页面上下文，因此旧解析方式的预测缓存不会被直接复用。

模板优先使用平台记录容器确定教育、实习、工作等经历序号。隐藏的原型记录、嵌套记录容器不占用可见经历的序号。原有实习优先及无实习栏目时才回退工作栏的规则继续适用。公司自定义的新字段、无法确定的章节继续交给原有匹配流程。

Moka 学校/专业选中后会清空 placeholder，仍按结构与可编辑搜索输入识别，不能因此跳过。固定菜单的输入用于过滤选项，不是任意文本答案：模板中已知的固定字段及年月选项必须从已扫描选项中选择，即使菜单可滚动。学校/专业远程检索及其它未确定的动态列表继续使用原有操作能力。证件号码旁的类型选择框标为“证件类型”，避免两个不同控件借用同一份号码资料。无法匹配的建议在写入前提示核对。

新增模板应提供去除个人信息的固定表单样本，证明重复经历与字段归属、菜单提交、日期精度、失败读回、用户修改保护，以及不触发网站保存/提交。通用输入、原文保持、反馈确认和延迟复核共用现有实现，不为每个平台复制一套 AI 流程。
