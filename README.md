# Resume Fill Assistant · Jev Apply（0.11.4 原型）

Chrome / Edge 浏览器扩展：在本机保存简历与个人资料，用 **DeepSeek 或 Jev** 识别网申字段，支持有依据的建议先填入、低置信标记及用户反馈学习，也保留单模型预览与手动填写。

## 0.11.4：按招聘平台模板解析

加入本地、带版本的 Moka / Hotjob / 北森模板。先验证平台组件结构，再用对应的字段标签、章节与经历容器解析；支持企业自有域名，不依赖易变的 CSS 完整后缀。只有域名匹配、结构未知或多个平台特征冲突时继续使用通用解析。侧栏显示识别结果，模板版本参与缓存身份。

经历序号由平台记录容器确定，隐藏原型和嵌套容器不占用可见记录序号。Moka 学校/专业选中后没有输入提示也继续核对；固定菜单的搜索框仅作为选项过滤，不能把公司名称等自由文本当成工作经验选项；类型选择框与证件号码输入框明确区分。保留按页面顺序遍历、原文填写、实习优先、用户修改保护及橙色反馈。

[平台适配范围与验证方法](docs/platform-templates.md)。飞书招聘目前使用通用解析，专用模板尚需实页样本验证；现有模板也不代表同平台所有版本或企业自定义字段已完全适配。

验证：84 项核心测试及 8 套相关浏览器回归通过，涵盖平台结构识别、自有域名、隐藏原型、经历新增与归属、选中后的学校/专业、固定选项、号码/类型区分、资料学习、北森控件、缓存和完整逐项核对。真实 Chrome / SHEIN Moka 页面识别并遍历 61 项，学校/专业进入核对，暂不适用或不支持从此前同规模扫描的 12 项降至 8 项。修复期间首轮新增填写并核验 14 项；最终版复测 35 秒，新增核验 1 项、核对一致 41 项、失败 0 项、待核对 11 项、不适用或不支持 8 项。原文/日期保留，未保存、提交或代为确认学习答案。多轮数据受页面初值、缓存和模型波动影响，不是受控性能对比，也不代表全表已完成。Windows 实机未复测。

## 0.11.3：按页面顺序逐项读取、匹配、填写

默认一键流程按扫描得到的页面控件顺序执行。空白和已有内容不分批：读取当前控件，核对已确认资料或调用 Jev 定位素材、DeepSeek 提取原文，完成本项填写与读回后才进入下一项。已有值与素材一致的仍经过核对并单独计数，无需重复改写；有依据的差异纠正并标橙。无素材、暂不支持或操作失败的逐项显示原因，其它字段继续处理。

整页遍历后统一检查保留结果和关联关系。技能名称/掌握程度等不再改变本轮的页面处理顺序；后续操作造成前面的值清空会撤销成功统计，关联问题标橙，未经最终读回通过的方案不写入加速缓存。原文、经历与格式检查仍保留；不会为了补空位编造信息。分析期间手动修改仍受保护，原生下拉框非空占位编号不再被误判成用户修改。

逐项分析可能比批量模型请求耗时更长；已确认资料和成功方案仍会本地复用。关闭默认顺序遍历选项时保留旧的补空白模式。只处理当前扫描可识别的控件，隐藏、同意条款、上传及不能操作的控件不会强行点击。网站保存/提交仍由用户执行。

验证：84 项核心测试、6 套相关浏览器回归通过，包括混合空白/已有值的顺序、前项完成后才分析后项、延迟清空、月份与学校专业、手动填写及反馈确认。真实 Chrome / SHEIN 页面扫描并遍历 61 项；首轮 69 秒新增填写 1 项、核对一致 40 项、失败 1 项（工作经验建议无匹配选项），已明确提示。最终版本复测 55 秒，新增填写 0 项、核对一致 39 项、失败 0 项、待人工核对 10 项、不适用或暂不支持 12 项。日期保留正确，未保存、提交或代为确认答案。模型结果有波动，遍历完成不代表全表填写完成。

## 0.11.2：逐项核对已有内容，修复 Moka 月份与学校专业

默认开启“逐项核对已有内容”：可填写字段无论是否已有值都进入匹配和核验。与素材一致的计为“核对一致”，不重复写入；有依据的差异纠正后标橙，无素材的保留现值并提示。不能自动操作或没有对应经历的控件单独列出原因，不混入已核对数量。手动确认和拒绝仍由用户决定。核对依旧遵守已确认资料优先、原文保持和经历归属规则；“一致”表示与采用的资料一致，不是独立事实认证。

纠正前再次比较网页值与扫描快照：分析期间的用户修改不会被旧答案覆盖。关闭“逐项核对”可继续使用仅补空白的模式；底部覆盖开关用于手动填写。

Moka 修复：选择年份自动生成的月份默认值不再阻止随后填入正确月份；已确认完整日期可直接拆成年/月。学校和专业支持先输入才出现的远程搜索菜单。选学校后专业控件被重新生成时，仅在同一经历、同一字段容器中重新定位；无准确目录选项时，通过该菜单提供的“添加学校/专业全称”及内部“添加”按钮提交原文，读回选中结果后才算成功。不会把搜索词或未提交的全称当作已填写，也不会点击招聘页面保存或提交。多行段落与单行职位/角色框不兼容时，提前提示核对，不会压缩改写。

验证：78 项核心测试及 9 套相关浏览器回归通过，包括年份带出默认月份、保留原月份、重扫后继续填写、延迟搜索、专业全称局部确认、控件重新生成、全字段核对及分析期间用户修改保护。真实 Chrome / SHEIN Moka 表单已补齐学校、专业、实习职位，纠正教育/实习/项目月份。修复后补填一轮新增核验 3 项；最终重复核对用时 40 秒，核对一致 42 项、失败 0、待人工核对 7、不适用或暂不支持 12。测试未保存或提交表单，未代为确认学习事实；不代表所有字段均已完成。Windows 实机未复测。

## 0.11.1：修复填入后清空，并提示关联字段冲突

普通文本框先点击激活、等待控件更新，再发送包含输入信息的事件；失焦时若浏览器侧栏占用焦点导致原生事件未触发，补发失焦事件，让网页提交控件状态并进行校验。仍以实际读回结果判断成功。

一键流程增加整轮延迟复核。侧栏保持打开、目标网页处于当前标签页时，每 1.5 秒继续核验本轮未确认的已填字段：发现清空或变化就撤销成功计数、移除对应预测缓存、显示橙色警告；不会自动覆盖用户修改或把修改擅自记为事实。重新扫描、新的一轮或关闭侧栏会结束上一轮监测；这不是保存到招聘网站后的验证。旧版本的预测缓存失效，个人资料、密钥和已确认学习资料保留。

技能名称先于掌握程度填写；同组技能名称缺失或写入失败时，掌握程度留待核对。个人毕业时间与最高学历对应教育结束时间按年月比较，不一致时两边均标橙，已有日期不自动改动。填写失败与关联冲突也属于橙色预警，不再只在总数中提示失败。

验证：75 项核心测试、8 套浏览器回归通过，包括延迟清空、缓存撤销、点击激活、缺失失焦事件、用户修改确认、Moka 与北森控件。真实 Chrome / 欣旺达页面已实测：技能名称填入成功，日期冲突出现警告；最终对证件号码空栏一键续填用时 12 秒，新增填入并核验 1 项、失败 0、待核对 21、跳过 41；网页“必填”提示消失。计数是本轮结果，不代表全表准确或全部完成。测试期间未保存、提交、上传或代为确认答案；Windows 实机尚未复测。

## 0.11.0：复用成功方案，等待异步级联菜单

快速填写会在本机缓存已实际填入并读回成功的方案。相同页面地址（含查询参数与路由）、页面上下文、字段语义、控件选项、启用素材与拒绝反馈没有改变时，再次填写可跳过模型分析。每次复用仍核对原文、经历和格式，并重新执行/读回；缓存不会把未经确认的答案变成已确认资料，仍标橙。已确认资料始终优先，严格模式不用该缓存。

字段选项、标签或经历变化时对应缓存不再命中；素材或反馈变化会让该代缓存整体失效。缓存仅限主页面、排除无法区分的重复字段，保存最多 7 天、96 项、约 2 MB；保留在当前浏览器，清除个人资料时一并删除，不进入资料导出或 PC 密钥文件。缓存故障不影响已经完成的填写。

修复三级地区菜单的时序问题：选完父级后等待实际子级选项出现和稳定，避免父级已稳定就误判子级缺失；旧分支仍在页面时不会提前点击。子级始终未加载时只报告该项失败，保留读回检查。

[本轮同类项目复查与借鉴说明](docs/research-and-adoption-2026-10-08.md)。仅借鉴设计并按现有代码重新实现，没有引入竞品依赖或新的权限。

验证：68 项核心/缓存测试、8 套浏览器回归通过。合成表单首次 2 次模型请求，再次打开后为 0 次；改变一个下拉字段的选项编号仅重分析该字段。约 1 秒异步加载的级联回归在旧版失败、新版通过。未在真实招聘网站或 Windows 实机重跑。

## 0.10.2：快速填写与超长校核隔离

默认“快速填写”：已确认资料本地复用，其余字段只做一次 Jev 素材定位和一次 DeepSeek 原文提取/控件适配，再做本地引用、经历、日期、长度和读回检查。省去逐答案对全部素材的独立交叉复核与自动第二轮修正。没有独立模型复核的建议均标橙等待确认，不把它们冒充为高置信结果；反馈确认后下次可直接复用。取消勾选快速填写可使用原有严格复核流程。

严格模式不再因一项超长而终止整页：校核只携带选中的选项及不重复的引用上下文；过大的字段组合拆成单项，仍超限的单项明确报错并跳过，其余继续。不会截断填写原文或把部分校核当成完整通过。未匹配、无素材和不合法的答案依然留空。

验证：62 项核心测试及快速反馈、严格协作、Moka、资料学习、手动填写、DeepSeek 共 6 套浏览器回归通过（模型使用模拟响应）。12 字段 / 21 素材的合成对照中，模型请求从 38 次降至 8 次；该数据不代表真实网站耗时。真实 Chrome 已观察到原始报错；因用户窗口持续切换，本版未在该真实表单重跑，也未保存或提交。

## 0.10.1：结果区只显示橙色预警

一键填写过程及完成后仅展示橙色待确认项。正常填入、已有内容、未匹配和失败项不再全量列成卡片，完成数量与失败数量保留在汇总提示中。接受、修改后确认或拒绝后立即移出列表；没有剩余预警时显示明确空状态。批量确认只作用于可见预警，隐藏项目不会被顺带填入。手动扫描和单模型填写仍保留完整预览，方便按需处理剩余字段。

## 0.10.0：先填低置信建议，再由你反馈

默认勾选“有素材的低置信建议也先填入，标橙待我确认”。低分不再单独造成留空：有效候选范围可继续提取，有原文依据、经历及控件格式通过本地检查的建议会填入；模型未通过或范围低置信时网页与侧栏标橙。多个允许范围的候选按模型置信度选最高项，仍标记待确认。无候选、模型明确没有素材、非法日期、跨经历原文、改写、未适配控件和接口故障不会借此绕过。可取消勾选恢复严格门槛。

- **接受此项并记住**：核验网页仍为该值后保存；多个项目可勾选后批量接受。
- **修改后接受**：在侧栏修改，再接受；只在网页仍保留刚才自动填的值时替换，避免覆盖你后续的网页改动。
- **采用网页修改并记住**：直接在网页改好后，读取当前值并核验保存。
- **拒绝此答案**：本地记录拒绝，网页标红，原值保留供手动修改或清除；下次同网站、同类目、同经历、同字段的同一答案不会再自动填入。可在资料页撤销。

接受与修改以当前网站为默认范围，学习的是字段、经历和确认值，不伪造模型置信度，不在线训练模型。下拉框保存选项文字，内部编号改变后仍可匹配。确认过的精确字段下次经过本地验证直接复用；没有稳定匹配的其它字段继续交给模型。反馈保存在当前浏览器本机，更新扩展时保留；卸载会删除。原有“读取已填页面”仍可核对并选择跨站使用。

修复：只需要修正格式时保留已通过对应/一致性检查的素材范围；重试未提供新答案时保留上一条有依据的建议，避免“建议正确却消失”。学习资料识别问号、括号提示以及学院/毕业时间的明确同义字段。校核疑问显示具体分数与门槛。

验证：57 项核心测试和 10 套 Chromium 浏览器回归通过。真实 Chrome 在已有页面续填，新增成功 11 项（9 项低置信标橙）、失败 0、仍待核对 21、跳过 31；未保存或提交。反馈接受/修改/拒绝用合成素材验证，真实待确认项留给用户决定。未做 Windows 实机验收。

## 0.9.2：修复一键填写的漏分配与误拦截

在真实 Chrome / 欣旺达表单复现了“单项能填、一键却不填”：0.9.1 一键只填入 1 项，60 项停在素材分配。此前单项操作验证不能代表一键完整流程已通过。

- Jev 的问题明确写出目标字段和经历，不再仅靠数组序号定位；模型上下文移除无关的同组字段名称，按可用素材范围分组，避免其它经历干扰。
- 同一属性的已确认结构化资料和已学习资料优先。字段身份及经历明确、原文和控件格式可确定验证时直接使用本地核验，避免姓名、性别、完整生日等被模型波动拦截。仍检查完整日期、唯一有效选项、长度、同一经历、素材变化及写入回读；没有匹配规则的字段仍走双模型。
- 审核明确区分日期格式转换、学历等价选项与改写内容。模型审核门槛保持不变；改写、跨经历取值和补造日期仍拒绝。
- 菜单打开前把字段移入视口；菜单未出现且没有其它已打开菜单时，仅重试一次。不能关联的菜单继续报错。
- 区分无候选素材、模型选了“无”、置信度不足、响应无效和页面操作失败，避免统一提示补充素材。

**真实一键验收（2026-09-26）**：最终版从初始表单启动，自动新增 2 组经历，63 项中填写并回读通过 19 项，待核对 42 项，操作失败 0 项，跳过 2 项。姓名、性别、完整出生日期、邮箱等确认资料稳定使用本地核验；模型负责其它素材匹配、提取及审核。未点击网站保存、提交或上传，也未改写简历素材。中间版本曾填入 20 项，表明模型判断仍有波动；本版不承诺全表填完。

**剩余问题**：除身高、体重、证件号码等缺少资料外，本科的学历和技能名称等有原文的字段也仍可能被低置信度或审核拦截。缺少完整日期、未提供的意向/调剂、未适配控件继续留待核对，不把这些状态计为成功。后续准确性优化仍有工作。

## 0.9.1：先补齐实际填写操作

本版只修复操作层，Jev / DeepSeek 的素材路由、准确性门槛和原文约束保持不变。

### 将两套 API key 保存到用户主目录

下载 [本地连接程序](https://github.com/GWTINYC/Resume_Fill_Assistant/releases/latest/download/jev-apply-local-keys.zip)，解压并按附带 README 安装一次：

1. 更新插件，在侧栏展开“PC 文件保存”，复制当前扩展 ID。
2. Windows 双击 `install-windows.bat`，粘贴 ID；Mac 运行 `install-macos.command`，粘贴 ID。无需管理员权限或备份密码。Windows 使用 .NET Framework 编译器（通常随系统提供），Mac 需要 Python 3。
3. 返回侧栏点击“连接 / 迁移到 PC 文件”，确认显示“PC 文件已连接”。以后保存密钥会同时写入 PC 文件与浏览器副本；PC 文件已有密钥时会自动读取。

文件位置：Mac `~/.resume-fill-assistant/api-keys.json`；Windows `%USERPROFILE%\.resume-fill-assistant\api-keys.json`。按用户要求明文保存，不设密码；目录和文件权限限制为当前用户（Windows 另保留 SYSTEM）。文件独立于扩展：更新、卸载扩展都不会删除它。重装后扩展 ID 仍已授权即可读回；换浏览器或扩展目录导致 ID 变化时，重跑安装脚本添加新 ID，已有密钥保留。同一电脑同一系统账户的 Chrome / Edge 可共用此文件；不同电脑不会自动同步。

未安装或无法连接时仍可使用浏览器副本，但界面明确显示“仅浏览器”，不能当作卸载后的备份。文件损坏不自动覆盖；写入失败会保留浏览器副本并提示，连接恢复后同步待保存值。“清除密钥”同时清除当前服务的 PC 文件项与浏览器副本，保留另一服务；已连接过的 PC 程序不可用时不会谎报清除成功。安装器不删除或重写 API key 文件。

新增 `nativeMessaging` 权限，仅连接本地程序；程序只接受已登记的扩展 ID，只能操作固定密钥文件，不接受任意文件路径，不联网、不常驻。资料 JSON 不包含密钥，简历/学习资料仍使用原本的浏览器存储及导出功能。

验证：42 项核心测试通过；故障注入覆盖编码、文件读取、空间不足、JSON 入口错误、保留旧素材与重试。Mac 完成本地程序真实协议测试、并发写入、600/700 权限检查，以及真实 Chromium native messaging 的浏览器副本迁移、全新浏览器配置恢复、单服务清除、损坏文件保护及断连状态测试。Windows C# 程序已用 C# 5 / .NET Framework 4.8 引用程序集编译检查，尚未在 Windows 实机运行；可在 Windows 用 `python tests/native-host.test.py` 运行原生协议测试。测试均使用虚构密钥，不访问用户真实密钥文件。

## 0.4.1：栏目语义匹配，内容原文填入

灵活性只用于选择对应类目：网页的“个人能力”可以对应素材的“个人技能”，填入内容直接复制素材原文，不做改写、润色、翻译、总结或补写。点击“一键启动 · 双 AI 协作填写”后：

2. **DeepSeek 匹配栏目与素材**：结合栏目含义、上下文和经历归属，选择对应原文片段 ID，插件取回完整文本和引用。
3. **插件检查原文**：引用必须逐字存在于对应素材；文本待填值必须是同一条引用中的连续原文，保留内部标点和空白。改写、跨段拼接以及超长原文会被拒绝。
4. **Jev 独立判断语义匹配**：检查类目是否对应、是否选对经历、是否遗漏限定词或截断段落导致歧义，以及素材是否冲突。名称不必相同，但关键词相近不等于用途相同。
5. **DeepSeek 重新匹配**：只对未通过或缺少合适素材的字段重新选择一次原文，再交给 Jev 复核；不以改写内容来迎合审核。
6. **插件自动填入并读回核验**：仅填入通过检查的字段，检查实际值与网页校验结果。无匹配素材、含义不明确或原文超长时留待人工核对，不自动缩写。

| 网页栏目 | 素材栏目 | 行为 |
| --- | --- | --- |
| 个人能力 | 个人技能 | 含义对应时，原文填入技能段落 |
| 工作职责 | 工作内容 | 确认同一段经历后，原文填入 |
| 求职意向 | 个人技能 | 用途不同，不用技能段落代填 |
| 实习公司 | 全职经历中的公司 | 经历不对应，不填 |

只有控件格式存在两类例外：原生日期/月控件可把已有完整日期转换为所需格式；固定选项可匹配语义等价的选项。普通文本保留素材语言和措辞，不根据岗位另写动机或推断能力。PDF 的“原文”指提取后保存的文本，可在资料页检查；不还原 PDF 版式。

建议把“个人技能”“自我介绍”“求职意向”等分别准备为完整段落，也可保存成自定义资料项。没有准备的答案留空，不自动创作。

已有内容默认跳过；允许覆盖仍需要用户明确勾选。不自动提交、不勾选条款、不操作附件。可点击“停止”阻止后续步骤；当前模型请求或已发出的单字段写入可能完成，已填内容保留。

一键流程的校核阶段会分块遍历全部启用资料，不只看 DeepSeek 选择的引文。每次 Jev 最多检查两个字段、八个问题，状态限制在 23,000 UTF-8 字节以内；本次协作最多 80 次校核请求。超过上限会停止自动填写并提示缩减范围，不静默跳过剩余资料。

PDF / TXT 多素材、本地持久保存、两套密钥隔离及原有 Jev / DeepSeek 单独模式继续保留。

## 安装与升级

建议使用最新稳定版 Chrome / Edge，最低声明版本为 Chromium 140，采用 Manifest V3。

1. 下载并解压 `jev-apply-extension.zip`。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
3. 打开“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择包含 `manifest.json` 的 `jev-apply` 文件夹，在工具栏固定扩展图标。

更新时覆盖原来的扩展文件夹，在扩展管理页点击“重新加载”，保持原路径和扩展身份。不要通过卸载重装来更新：卸载扩展、清除浏览器配置或改变扩展身份可能导致本地数据丢失。Chrome 和 Edge 各自保存资料；0.8 的 PC 密钥文件可以由同一系统账户的两个浏览器共用。

## 使用

1. 导入 PDF / TXT，补充个人资料或备注；素材自动保存，资料和备注点击“保存个人资料”。
2. 在侧栏“密钥配置 / 单模型模式”中分别选择 DeepSeek、Jev，保存各自的官方 API key。这里只是配置两套密钥；一键协作始终同时使用两者。
3. 到网申页点击扩展图标，然后点击“一键启动 · 双 AI 协作填写”。无需先扫描或在两个模型之间手动切换。
4. 等待原文匹配、校核和自动填入。默认低置信但有依据的建议也填写并标橙，显示在已填数量中，另列出待确认数量。逐项接受、修改或拒绝，也可批量接受勾选项。
5. 自行处理剩余项目、检查全部内容，再提交申请。进入下一页后再次一键启动。

也可继续使用“单模型与手动操作”：扫描页面 → 点击所选服务识别 → 预览、编辑、勾选 → 填入。修改已校核的答案属于用户手动调整，不代表修改后的文本仍获得了模型校核。

### 单模型模式的区别

| 项目 | DeepSeek | Jev |
| --- | --- | --- |
| 当前模型 | `deepseek-flash` | `jev-1.13.0` |
| 主要用途 | 按语义选择素材原文，生成填写计划 | 在已定义的资料项和网页选项中做语义选择 |
| 是否使用素材全文和备注 | 使用启用素材的文本与已保存备注 | 不使用 |
| 结果校验 | 字段 ID、控件支持情况、原文引用存在、待填值逐字匹配、选项合法性、日期格式等 | 候选 ID、概率与 confidence 门槛 |
| 用户核对 | 提议值、引用出处、对应经历 | 资料映射、选项含义 |

DeepSeek 的输出不是任意浏览器脚本。插件只允许填写扫描到的受支持字段，不运行模型提供的 JavaScript、选择器、导航或提交指令。逐字检查可以拦截改写，但不能证明栏目语义、段落完整性和经历匹配正确；这些由 Jev 校核，最终仍需检查。

## 素材与本地持久化

- **PDF**：最大 20 MB，文本提取支持 40 页以内且有文本层的文件。加密、扫描版等文件可保留原件，读取失败会明确提示；不含 OCR。
- **TXT**：最大 2 MB，支持 UTF-8（包括 BOM）、带 BOM 的 UTF-16，以及 UTF-8 无法解码时回退 GB18030/GBK。拒绝空白或包含二进制控制字符的文件。
- 可同时保留 PDF 与 TXT。添加文件不会覆盖旧素材；需要更新时使用“替换这份素材”。
- 在素材列表选择一项后，可查看文本、查看原文件、下载原件或删除。下载保留原文件字节和文件名。
- 每份素材可勾选是否在智能填写或双 AI 协作中使用。关闭仅影响模型请求，不删除本地文件。
- 素材保存在本地 IndexedDB；个人资料、备注、服务选择和密钥副本保存在扩展本地存储。连接本地程序后，两套 API key 另存到用户主目录的独立文件。
- 资料与备注可导出/导入 JSON。密钥不包含在资料 JSON 中，素材原文件通过下载功能单独备份。
- 结构化个人资料优先于素材中冲突的信息；无法确定时提示模型跳过。
- 单次 DeepSeek 请求使用的资料文本上限为 100,000 字符，过长时明确报错，请取消部分素材或缩短资料；不会静默截断。

扩展没有自己的服务器、遥测或云同步。本地存储没有额外加密；密钥不写入源码或分发包。

## 数据发送范围

**导入、编辑、扫描、本地名称匹配均在本机执行。** 点击一键协作或单模型智能识别按钮才调用模型：

- **一键协作**：启用素材文本、已保存个人资料、备注、网页字段/页面上下文和拟填答案会发送给 DeepSeek 与 Jev；不上传原文件。

- **单独使用 Jev**：字段标签、类型、邻近标题、选项文字、资料项目名称；选项语义匹配时额外发送相关的单项资料值。不发送素材全文或备注。
- **单独使用 DeepSeek**：本批网页字段描述、已保存个人资料的标签和值、补充备注、启用素材的文本。不会上传原始 PDF / TXT 二进制文件。
- 填入后，目标网站自身可能即时保存输入。插件不控制目标网站的数据处理。

接口固定为官方服务：

- `POST https://api.typesafe.ai/v1/systemone`
- `POST https://api.deepseek.com/chat/completions`

权限为 activeTab、scripting、storage、sidePanel、nativeMessaging，加上述两个 API 域名；没有全站常驻读取权限。模型密钥只能由可信扩展上下文读取。

## 支持的网页操作

- 标准 HTML 文本、邮箱、电话、URL、数字输入框、textarea。
- 标准 select 单选下拉框、radio 单选组、原生 date / month。
- 从 label、aria-label、aria-labelledby、placeholder、name 和邻近标题识别字段。
- 同源、权限允许的 iframe，每框架最多扫描 100 项。
- 写入后发送 input/change 事件；具体网站框架仍需实际验证。
- 页面地址改变、字段失效、资料更新或 DeepSeek 素材变化时要求重新扫描。
- 不自动补造缺失日期；无效日期回滚；不默认覆盖已有内容。

能关联到唯一选项列表的单选下拉（ARIA / Phoenix / 已适配的 Moka Sugar）及 Phoenix 单选支持点击选择和读回。仍需人工或专项适配：无明确选项关联的自制下拉、级联地区、尚未适配的自定义日历、多选 checkbox、Shadow DOM、不可访问的跨域 iframe，以及无法明确识别分组或按钮的“新增经历”区块。插件不会点击下一步、提交、条款同意、验证码、签名或上传附件。Moka 的验证范围见 0.6 说明；北森、Workday 及其它控件变体尚未完成真实站点全流程验收。

## 模型配置与验证

DeepSeek 根据调研时的官方文档采用 `deepseek-flash`、`response_format: {type: "json_object"}`、`thinking: {type: "disabled"}`，每批最多 12 个字段。空内容、无效 JSON、不完整输出或接口错误会提示；未知字段、无出处引文、非原文文本、超长内容、重复字段、非法选项和不合法日期不进入执行计划。不使用模型自报置信度作为自动正确性的保证。

单独使用 Jev 时，固定为 `jev-1.13.0`，每批最多 6 个问题；选中概率与 confidence 均至少为 0.80 才接受建议。该门槛是初始设置，不代表 80% 的正确率保证。

协作的高置信判断门槛（0.10.0 默认允许未达门槛的有依据建议先填写并标橙；取消勾选时仍阻止自动填入）：事实字段和原文段落均要求类目对应概率 ≥0.90、原文偏离/不完整风险 ≤0.10、冲突风险 ≤0.10。字段类型 Choice 的选中概率与 confidence 均需 ≥0.80。这些是工程初始门槛，不是经过业务数据校准的准确率承诺；两个模型意见一致也不能保证正确。逐字匹配由本地代码额外强制检查，不由概率决定。

验证范围：

- 35 项核心测试：原有行为、TXT 编码、来源限制、完整分块校核、反馈修正、逐字匹配、禁止改写/翻译/拼接、日期格式例外、超长拦截、取消、数据变化和读回失败等。
- Chrome for Testing 与 Edge：Jev 原有扫描/匹配/填写流程，PDF 读写、重启恢复、默认跳过、事件、iframe、日期回滚。
- Chrome for Testing 与 Edge：模拟 DeepSeek 官方 API 完成 TXT/备注识别、出处展示、编辑、填入、异常响应处理、服务/密钥隔离、多素材与重启恢复。
- 新增 Chrome for Testing / Edge 双 AI 协作端到端测试：一次点击完成扫描、原文匹配、校核、重新匹配、复核、填入、读回；验证“个人能力”匹配“个人技能”并保留多行原文、改写被拦截、错配经历、缺失薪资、停止与审查服务故障等路径。
- 0.4 的真实 Jev 小样本探测对应旧的表达策略，不作为本版语义匹配策略的验证。0.5 的真实测试范围见上方说明。
- 0.5 已完成用户授权的真实双 API 与 Edge 本地页面测试；侧栏整链路使用模拟接口回归验证，数据见上方“本轮真实测试及边界”。
- 正式 Chrome 尚未通过普通界面手动安装验证。自动化使用 Chrome for Testing；测试临时副本添加 localhost 权限，交付包没有该权限。
- 真实 API 测试仅向两个已配置的官方服务发送用户授权的素材文本；原始文件、个人测试结果及凭证未提交仓库，未操作招聘账户。
