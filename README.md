# Resume Fill Assistant · Jev Apply（0.9.1 原型）

Chrome / Edge 浏览器扩展：在本机保存简历与个人资料，用 **DeepSeek 或 Jev** 识别网申字段，支持一键协作校核后自动填入，也保留单模型预览与手动填写。

[下载最新版插件](https://github.com/GWTINYC/Resume_Fill_Assistant/releases/latest/download/jev-apply-extension.zip) · [版本发布记录](https://github.com/GWTINYC/Resume_Fill_Assistant/releases)

## 0.9.1：先补齐实际填写操作

本版只修复操作层，Jev / DeepSeek 的素材路由、准确性门槛和原文约束保持不变。

- 北森 Phoenix 弹窗单选：打开菜单，点击实际选择图标，检查已选区，再点击弹窗内部“确定”，最后读取字段值。扫描使用弹窗“取消”，不会提交试探选择。
- 北森地区弹窗：按完整省市区路径逐层进入，在最终层选择并确认；不把进入下一层当作已选择。只支持可确认的单选模式。
- 北森日历：支持完整年月日和教育经历年月控件，操作年份、月份和日期面板；拒绝缺失日期精度、禁用日期和无法确认的结果。修复年月控件误点外层年份按钮的问题。
- 每项增加“直接指定并填入此项”：输入已确认的值即可单独测试执行，不调用模型。手动操作也增加延迟回读，网页清空或未保留的值不会计为成功。
- 失败提示区分未加载、无匹配、未进入已选区、确认未关闭、日期不可选及确认后未保留。

Chrome 在欣旺达真实页面验证了出生日期、邮箱、教育起止月份、学历、民族弹窗单选和籍贯省市级联的写入与回读；未点击招聘页保存或提交。地区值沿用用户已手填确认的资料；异常分支和完整省市区三级路径另用合成页面验证。47 项核心测试及北森控件、手动单项、复杂下拉、Moka、常规填写、招聘页、DeepSeek、双模型协作和资料学习回归通过；模型回归使用模拟响应，本轮操作验收不调用模型。未在 Windows 实机验证。

**仍需注意**：多选、其它未适配日历和没有可靠 DOM 关联的控件仍可能需手动处理。本版不代表所有字段都能自动匹配到素材；操作支持补齐后，再处理漏匹配和错配。

## 0.9：Jev 先定位素材，DeepSeek 再提取与适配

一键流程调整为：补足经历栏位 → **Jev 为每个字段选择素材范围** → **DeepSeek 在该范围内提取原文、转换日期或选择等价选项** → 校核 → 执行与读回。Jev 按字段含义、章节及经历序号匹配，允许“个人能力 / 个人技能”等同义类目。范围保留原始文本位置，DeepSeek 可以从句子中提取一个准确事实，不再要求该事实必须提前切成独立片段。

代码验证引用必须位于指定范围；拒绝跨记录取值、改写和编造日期。Jev 不确定、多个范围同时匹配或没有原文时留待核对。提取失败可重新定位一次；保留原有独立校核。手动确认资料的优先级、实习优先、无实习章节才回退工作栏的规则不变。单模型模式仍可使用。

下拉适配新增：

- Ant Design / Element 单选组件与页面外部挂载的菜单；支持 mousedown 触发，读取选中标签而不是把搜索词视为已选择。
- 搜索式下拉：按素材原文搜索，等待延迟返回的选项，唯一精确匹配后点击并回读。选项重排不再直接判失败；禁用项、当前列表中的同名歧义仍拒绝。
- 虚拟滚动：有界滚动寻找初始不可见的目标；不再仅依赖扫描时出现的几项。测试覆盖 300 项列表中的第 186 项。
- Ant / Element 省市区级联：素材提供完整路径时逐级匹配和点击，最终完整路径须与素材一致。缺少层级、路径有歧义或结果未提交时明确报错。
- 错误码区分菜单关联失败、无匹配项、同名歧义、级联不完整和点击后未保留选择。搜索失败恢复原查询文字；已有值默认跳过。

**边界**：多选、自定义日历、没有可靠 DOM/ARIA 关联的控件仍可能需要手动处理。远程搜索和级联使用原文精确匹配，不猜测地址简称或不存在的选项；滚动有次数上限。长素材范围用于 Jev 分类的预览会标注省略，DeepSeek 得到完整指定范围。已知章节/记录边界不明确的素材仍需核对；此版本不承诺所有招聘站点适配。

**安装**：下载上方 `jev-apply-extension.zip`，解压后加载里面的 `jev-apply` 文件夹。GitHub 的 Source code 压缩包与源码 `src` **不能直接加载**，必须先 `npm ci && npm run build` 再加载 `dist`。更新已有扩展时，将安装包内文件覆盖到原加载目录并点击重新加载，无需卸载。

验证：47 项核心测试；本地 Chromium 的复杂下拉、Moka、完整双模型协作、经历新增、学习资料、单模型及导入错误回归。模型响应使用模拟官方接口，素材为合成数据；未在 Windows 或真实招聘页面执行本版本的完整双模型验收，未保存或提交招聘申请。

## 0.8：失败诊断与卸载后仍保留的 PC 密钥文件

TXT / PDF 导入失败现在显示 **错误码、失败环节、处理办法、原文件/文本是否已保存**，并提供可复制的诊断信息。诊断不含密钥、素材正文、文件名或完整路径。覆盖文件类型/大小、空文件、编码、二进制/伪装格式、文件读取失败、本地数据库占用/超时、空间不足、权限错误、PDF 解析、界面后续处理失败。把 TXT 误选到“导入资料 JSON”时会明确提示正确入口；界面模块未加载或未捕获错误也不再无声失败。

### 将两套 API key 保存到用户主目录

下载 [本地连接程序](https://github.com/GWTINYC/Resume_Fill_Assistant/releases/latest/download/jev-apply-local-keys.zip)，解压并按附带 README 安装一次：

1. 更新插件，在侧栏展开“PC 文件保存”，复制当前扩展 ID。
2. Windows 双击 `install-windows.bat`，粘贴 ID；Mac 运行 `install-macos.command`，粘贴 ID。无需管理员权限或备份密码。Windows 使用 .NET Framework 编译器（通常随系统提供），Mac 需要 Python 3。
3. 返回侧栏点击“连接 / 迁移到 PC 文件”，确认显示“PC 文件已连接”。以后保存密钥会同时写入 PC 文件与浏览器副本；PC 文件已有密钥时会自动读取。

文件位置：Mac `~/.resume-fill-assistant/api-keys.json`；Windows `%USERPROFILE%\.resume-fill-assistant\api-keys.json`。按用户要求明文保存，不设密码；目录和文件权限限制为当前用户（Windows 另保留 SYSTEM）。文件独立于扩展：更新、卸载扩展都不会删除它。重装后扩展 ID 仍已授权即可读回；换浏览器或扩展目录导致 ID 变化时，重跑安装脚本添加新 ID，已有密钥保留。同一电脑同一系统账户的 Chrome / Edge 可共用此文件；不同电脑不会自动同步。

未安装或无法连接时仍可使用浏览器副本，但界面明确显示“仅浏览器”，不能当作卸载后的备份。文件损坏不自动覆盖；写入失败会保留浏览器副本并提示，连接恢复后同步待保存值。“清除密钥”同时清除当前服务的 PC 文件项与浏览器副本，保留另一服务；已连接过的 PC 程序不可用时不会谎报清除成功。安装器不删除或重写 API key 文件。

新增 `nativeMessaging` 权限，仅连接本地程序；程序只接受已登记的扩展 ID，只能操作固定密钥文件，不接受任意文件路径，不联网、不常驻。资料 JSON 不包含密钥，简历/学习资料仍使用原本的浏览器存储及导出功能。

验证：42 项核心测试通过；故障注入覆盖编码、文件读取、空间不足、JSON 入口错误、保留旧素材与重试。Mac 完成本地程序真实协议测试、并发写入、600/700 权限检查，以及真实 Chromium native messaging 的浏览器副本迁移、全新浏览器配置恢复、单服务清除、损坏文件保护及断连状态测试。Windows C# 程序已用 C# 5 / .NET Framework 4.8 引用程序集编译检查，尚未在 Windows 实机运行；可在 Windows 用 `python tests/native-host.test.py` 运行原生协议测试。测试均使用虚构密钥，不访问用户真实密钥文件。

## 0.7：学习手动填好的页面

在已填好的网申页打开侧栏，点击 **读取已填页面**，核对并勾选要保留的资料，再点击 **确认并保存勾选资料到本机**。读取和保存均不调用模型，也不修改招聘表单，不打开下拉框、不点击网站保存。

- 读取当前可访问页面中的非空文本、选中项的显示文字、单选、多选组和只读/禁用日期等已有值，保留多行文本。新增 Hotjob / Ant Design 的标题、重复经历及已选值识别；不会把下拉内部搜索文字或选项编码当答案。每个框架最多读取 300 项，单值上限 10,000 字符；不读取文件内容、密码、验证码和同意声明。
- 页面已有值不一定都是用户手动填写的，插件无法自动证明其准确性。预览可修改字段名称、类目、经历序号、值和适用范围；经历序号需要与素材中的记录顺序一致。家庭资料与本人资料分开，证件号等默认不勾选；与应聘有关的意向/调剂等默认仅用于当前网站，需手动勾选。
- 确认后形成独立的本地学习资料，带来源网站和保存时间，不存 URL 查询参数或 Cookie。同一范围、类目、经历及字段重复学习会更新原项；原 PDF / TXT 和结构化资料不被覆盖。
- 后续自动填写优先参考匹配的已确认资料。常见字段别名由本地规则对应，长尾语义匹配仍由模型判断；DeepSeek 挑选原文、Jev 继续校核；本地拒绝用其它经历、家庭资料或已被确认值替代的旧资料填入同一已识别字段。确认值只覆盖同一项，不意味着整份旧简历都失效。
- 资料页可编辑、停用、删除；JSON 导出/导入包含学习资料。旧版 JSON 导入不删除现有学习资料；含学习资料的新 JSON 导入需预览后保存，会替换学习资料集合。停用或删除后恢复参考原素材。

学习资料仅在之后启动智能填写时，按适用范围随资料发送到用户已配置的模型服务。这里的“学习”是保存可复用资料，不是训练模型权重。未知控件、不可访问 iframe 和尚未展开/加载的内容仍可能读不到。读取成功也不等于已经支持对该类自定义控件自动写入。

推荐的反复学习流程：

1. 在招聘网页填好并核对内容，再点击侧栏的 **读取已填页面**。
2. 检查每项的内容、资料类目、经历序号和适用范围，点击 **确认并保存勾选资料到本机**。学校、公司、项目等字段缺少明确的经历归属时，默认不勾选且仅限当前网站；请先修正类目和序号，需要跨站复用时再调整范围。
3. 到下一份申请中扫描、匹配并核对填写结果；改正网页上的错误后，再次读取并确认保存。只修改网页不会自动更新学习资料；同一范围、类目、序号和字段的确认值才会更新原项。

经历当前按“类目 + 第几条”对应，不会通过学校、公司或项目名称自动识别同一段经历。不同网站的经历顺序必须与资料一致；新增、删除或调整经历顺序后，要核对该类目的全部已学习字段，避免新旧字段混在同一序号。无法确认归属的经历字段不会自动复用学习资料，旧版误存为基本信息的学校等字段也受此保护；仍可在网页手填后核对学习。

验证：39 项核心测试；新增完整浏览器流程验证只读采集无点击/input/change 事件、确认前不保存且不调用 API、确认时编辑、去重更新、跨页面复用、双模型优先使用确认值、原文保留、停用、JSON 迁移和浏览器重启持久化。另覆盖超过 100 项、长选项不截断、只读及禁用值。六套既有浏览器回归通过。本轮真实 Chrome 页面仅做只读结构与已填值读取检查；站点有自动保存，因此未改字段、未点击保存或提交。完整流程以合成数据和模拟官方 API 验证，用户页面内容未写入仓库或发布包。

## 0.5.1：一键补足经历栏位

一键协作现在先核对素材中的记录数量与页面栏位数量。明确识别到两段实习、页面只有一组时，会点击该章节唯一的“添加实习经历”或“新增实习经历”，等待新增成功，重新扫描后再分配原文。已有足够栏位时不点击，也不删除多余栏位。单模型扫描不会自动新增。

当前适配可识别 `.form` 记录分组与章节标题的页面（含本地重建页/Phoenix 页面结构）；按钮名称须准确对应教育、实习、工作或项目章节。来源数量依据原文索引中已明确分开的记录，无法解析多个项目边界时不会猜测数量。多份材料数量不一致、章节/按钮不唯一或原值发生变化时停止并提示人工处理。

每次只点击一次，并确认记录数恰好增加一组、已有文本和选择均保留。3 秒内未确认新增会停止；同一页面不会立即重复点击。单类最多 10 条、一次启动最多新增 12 组。停止后不发起下一次新增；已发出的单次操作可能完成。不会点击提交、下一页或同意条款。

验证新增：Chrome for Testing 与 Edge 的侧栏一键端到端测试（模拟 API）验证自动新增、重新扫描、两模型填写第二段、保留已填第一段和重复启动不重复添加；页面回归验证无响应锁定和提交按钮排除。真实招聘站点仍需实际验证。

### 本轮真实测试及边界

用用户授权的素材和既有 Edge 密钥，在 Edge 的本地重建页调用真实 DeepSeek、Jev 接口。最新完整运行：66 项中填入并读回核验 21 项、待核对 41 项、附件/多选等跳过 4 项。逐项对照材料，21 项已填内容未发现错值或跨教育/实习串填。人工选定的 26 个有素材可匹配栏目中仍漏填 5 项（全局毕业时间、自我评价、本科学历、技能名称、第一段实习内容），不能把所有留空都归为资料缺失。

这是一份材料、一个重建页面的功能测试，不是泛化准确率，也不是真实招聘站点验收。完整一键侧栏另有 Chrome for Testing / Edge 模拟接口回归测试。

存档不包含原站脚本和未展开的选项全集，实验页补充了明确标注的测试选项，日期换成原生 date/month。真实站点的自定义日历、级联/虚拟滚动列表、多选和动态新增经历仍需专门适配；0.5.1 可补足明确识别的经历分组，其余结构仍需手动添加；插件不切换页面。原文索引目前识别常见中文标题和“硕士/本科：”“公司：”记录边界，无法明确分段的材料仍需人工核对。

## 0.4.1：栏目语义匹配，内容原文填入

灵活性只用于选择对应类目：网页的“个人能力”可以对应素材的“个人技能”，填入内容直接复制素材原文，不做改写、润色、翻译、总结或补写。点击“一键启动 · 双 AI 协作填写”后：

1. **插件扫描并建立快照**：读取可见字段、选项、页面标题与相关标题，记录当前资料与素材版本。
2. **DeepSeek 匹配栏目与素材**：结合栏目含义、上下文和经历归属，选择对应原文片段 ID，插件取回完整文本和引用。
3. **插件检查原文**：引用必须逐字存在于对应素材；文本待填值必须是同一条引用中的连续原文，保留内部标点和空白。改写、跨段拼接以及超长原文会被拒绝。
4. **Jev 独立判断语义匹配**：检查类目是否对应、是否选对经历、是否遗漏限定词或截断段落导致歧义，以及素材是否冲突。名称不必相同，但关键词相近不等于用途相同。
5. **DeepSeek 重新匹配**：只对未通过或缺少合适素材的字段重新选择一次原文，再交给 Jev 复核；不以改写内容来迎合审核。
6. **插件自动填入并读回核验**：仅填入通过检查的字段，检查实际值与网页校验结果。无匹配素材、含义不明确或原文超长时留待人工核对，不自动缩写。

| 网页栏目 | 素材栏目 | 行为 |
| --- | --- | --- |
| 个人能力 | 个人技能 | 含义对应时，原文填入技能段落 |
| 工作职责 | 工作内容 | 确认同一段经历后，原文填入 |
| 求职意向 | 个人技能 | 用途不同，不用技能段落代填 |
| 实习公司 | 全职经历中的公司 | 经历不对应，不填 |

只有控件格式存在两类例外：原生日期/月控件可把已有完整日期转换为所需格式；固定选项可匹配语义等价的选项。普通文本保留素材语言和措辞，不根据岗位另写动机或推断能力。PDF 的“原文”指提取后保存的文本，可在资料页检查；不还原 PDF 版式。

建议把“个人技能”“自我介绍”“求职意向”等分别准备为完整段落，也可保存成自定义资料项。没有准备的答案留空，不自动创作。

已有内容默认跳过；允许覆盖仍需要用户明确勾选。不自动提交、不勾选条款、不操作附件。可点击“停止”阻止后续步骤；当前模型请求或已发出的单字段写入可能完成，已填内容保留。

一键流程的校核阶段会分块遍历全部启用资料，不只看 DeepSeek 选择的引文。每次 Jev 最多检查两个字段、八个问题，状态限制在 23,000 UTF-8 字节以内；本次协作最多 80 次校核请求。超过上限会停止自动填写并提示缩减范围，不静默跳过剩余资料。

PDF / TXT 多素材、本地持久保存、两套密钥隔离及原有 Jev / DeepSeek 单独模式继续保留。

## 安装与升级

建议使用最新稳定版 Chrome / Edge，最低声明版本为 Chromium 140，采用 Manifest V3。

1. 下载并解压 `jev-apply-extension.zip`。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
3. 打开“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择包含 `manifest.json` 的 `jev-apply` 文件夹，在工具栏固定扩展图标。

更新时覆盖原来的扩展文件夹，在扩展管理页点击“重新加载”，保持原路径和扩展身份。不要通过卸载重装来更新：卸载扩展、清除浏览器配置或改变扩展身份可能导致本地数据丢失。Chrome 和 Edge 各自保存资料；0.8 的 PC 密钥文件可以由同一系统账户的两个浏览器共用。

## 使用

1. 导入 PDF / TXT，补充个人资料或备注；素材自动保存，资料和备注点击“保存个人资料”。
2. 在侧栏“密钥配置 / 单模型模式”中分别选择 DeepSeek、Jev，保存各自的官方 API key。这里只是配置两套密钥；一键协作始终同时使用两者。
3. 到网申页点击扩展图标，然后点击“一键启动 · 双 AI 协作填写”。无需先扫描或在两个模型之间手动切换。
4. 等待原文匹配、校核、必要的重新匹配和自动填入。侧栏会列出已填并核验、待人工核对、填写失败和跳过的项目，并保留出处与校核结果。
5. 自行处理剩余项目、检查全部内容，再提交申请。进入下一页后再次一键启动。

也可继续使用“单模型与手动操作”：扫描页面 → 点击所选服务识别 → 预览、编辑、勾选 → 填入。修改已校核的答案属于用户手动调整，不代表修改后的文本仍获得了模型校核。

### 单模型模式的区别

| 项目 | DeepSeek | Jev |
| --- | --- | --- |
| 当前模型 | `deepseek-flash` | `jev-1.13.0` |
| 主要用途 | 按语义选择素材原文，生成填写计划 | 在已定义的资料项和网页选项中做语义选择 |
| 是否使用素材全文和备注 | 使用启用素材的文本与已保存备注 | 不使用 |
| 结果校验 | 字段 ID、控件支持情况、原文引用存在、待填值逐字匹配、选项合法性、日期格式等 | 候选 ID、概率与 confidence 门槛 |
| 用户核对 | 提议值、引用出处、对应经历 | 资料映射、选项含义 |

DeepSeek 的输出不是任意浏览器脚本。插件只允许填写扫描到的受支持字段，不运行模型提供的 JavaScript、选择器、导航或提交指令。逐字检查可以拦截改写，但不能证明栏目语义、段落完整性和经历匹配正确；这些由 Jev 校核，最终仍需检查。

## 素材与本地持久化

- **PDF**：最大 20 MB，文本提取支持 40 页以内且有文本层的文件。加密、扫描版等文件可保留原件，读取失败会明确提示；不含 OCR。
- **TXT**：最大 2 MB，支持 UTF-8（包括 BOM）、带 BOM 的 UTF-16，以及 UTF-8 无法解码时回退 GB18030/GBK。拒绝空白或包含二进制控制字符的文件。
- 可同时保留 PDF 与 TXT。添加文件不会覆盖旧素材；需要更新时使用“替换这份素材”。
- 在素材列表选择一项后，可查看文本、查看原文件、下载原件或删除。下载保留原文件字节和文件名。
- 每份素材可勾选是否在智能填写或双 AI 协作中使用。关闭仅影响模型请求，不删除本地文件。
- 素材保存在本地 IndexedDB；个人资料、备注、服务选择和密钥副本保存在扩展本地存储。连接本地程序后，两套 API key 另存到用户主目录的独立文件。
- 资料与备注可导出/导入 JSON。密钥不包含在资料 JSON 中，素材原文件通过下载功能单独备份。
- 结构化个人资料优先于素材中冲突的信息；无法确定时提示模型跳过。
- 单次 DeepSeek 请求使用的资料文本上限为 100,000 字符，过长时明确报错，请取消部分素材或缩短资料；不会静默截断。

扩展没有自己的服务器、遥测或云同步。本地存储没有额外加密；密钥不写入源码或分发包。

## 数据发送范围

**导入、编辑、扫描、本地名称匹配均在本机执行。** 点击一键协作或单模型智能识别按钮才调用模型：

- **一键协作**：启用素材文本、已保存个人资料、备注、网页字段/页面上下文和拟填答案会发送给 DeepSeek 与 Jev；不上传原文件。

- **单独使用 Jev**：字段标签、类型、邻近标题、选项文字、资料项目名称；选项语义匹配时额外发送相关的单项资料值。不发送素材全文或备注。
- **单独使用 DeepSeek**：本批网页字段描述、已保存个人资料的标签和值、补充备注、启用素材的文本。不会上传原始 PDF / TXT 二进制文件。
- 填入后，目标网站自身可能即时保存输入。插件不控制目标网站的数据处理。

接口固定为官方服务：

- `POST https://api.typesafe.ai/v1/systemone`
- `POST https://api.deepseek.com/chat/completions`

权限为 activeTab、scripting、storage、sidePanel、nativeMessaging，加上述两个 API 域名；没有全站常驻读取权限。模型密钥只能由可信扩展上下文读取。

## 支持的网页操作

- 标准 HTML 文本、邮箱、电话、URL、数字输入框、textarea。
- 标准 select 单选下拉框、radio 单选组、原生 date / month。
- 从 label、aria-label、aria-labelledby、placeholder、name 和邻近标题识别字段。
- 同源、权限允许的 iframe，每框架最多扫描 100 项。
- 写入后发送 input/change 事件；具体网站框架仍需实际验证。
- 页面地址改变、字段失效、资料更新或 DeepSeek 素材变化时要求重新扫描。
- 不自动补造缺失日期；无效日期回滚；不默认覆盖已有内容。

能关联到唯一选项列表的单选下拉（ARIA / Phoenix / 已适配的 Moka Sugar）及 Phoenix 单选支持点击选择和读回。仍需人工或专项适配：无明确选项关联的自制下拉、级联地区、尚未适配的自定义日历、多选 checkbox、Shadow DOM、不可访问的跨域 iframe，以及无法明确识别分组或按钮的“新增经历”区块。插件不会点击下一步、提交、条款同意、验证码、签名或上传附件。Moka 的验证范围见 0.6 说明；北森、Workday 及其它控件变体尚未完成真实站点全流程验收。

## 模型配置与验证

DeepSeek 根据调研时的官方文档采用 `deepseek-flash`、`response_format: {type: "json_object"}`、`thinking: {type: "disabled"}`，每批最多 12 个字段。空内容、无效 JSON、不完整输出或接口错误会提示；未知字段、无出处引文、非原文文本、超长内容、重复字段、非法选项和不合法日期不进入执行计划。不使用模型自报置信度作为自动正确性的保证。

单独使用 Jev 时，固定为 `jev-1.13.0`，每批最多 6 个问题；选中概率与 confidence 均至少为 0.80 才接受建议。该门槛是初始设置，不代表 80% 的正确率保证。

协作校核初始门槛：事实字段和原文段落均要求类目对应概率 ≥0.90、原文偏离/不完整风险 ≤0.10、冲突风险 ≤0.10。字段类型 Choice 的选中概率与 confidence 均需 ≥0.80。这些是工程初始门槛，不是经过业务数据校准的准确率承诺；两个模型意见一致也不能保证正确。逐字匹配由本地代码额外强制检查，不由概率决定。

验证范围：

- 35 项核心测试：原有行为、TXT 编码、来源限制、完整分块校核、反馈修正、逐字匹配、禁止改写/翻译/拼接、日期格式例外、超长拦截、取消、数据变化和读回失败等。
- Chrome for Testing 与 Edge：Jev 原有扫描/匹配/填写流程，PDF 读写、重启恢复、默认跳过、事件、iframe、日期回滚。
- Chrome for Testing 与 Edge：模拟 DeepSeek 官方 API 完成 TXT/备注识别、出处展示、编辑、填入、异常响应处理、服务/密钥隔离、多素材与重启恢复。
- 新增 Chrome for Testing / Edge 双 AI 协作端到端测试：一次点击完成扫描、原文匹配、校核、重新匹配、复核、填入、读回；验证“个人能力”匹配“个人技能”并保留多行原文、改写被拦截、错配经历、缺失薪资、停止与审查服务故障等路径。
- 0.4 的真实 Jev 小样本探测对应旧的表达策略，不作为本版语义匹配策略的验证。0.5 的真实测试范围见上方说明。
- 0.5 已完成用户授权的真实双 API 与 Edge 本地页面测试；侧栏整链路使用模拟接口回归验证，数据见上方“本轮真实测试及边界”。
- 正式 Chrome 尚未通过普通界面手动安装验证。自动化使用 Chrome for Testing；测试临时副本添加 localhost 权限，交付包没有该权限。
- 真实 API 测试仅向两个已配置的官方服务发送用户授权的素材文本；原始文件、个人测试结果及凭证未提交仓库，未操作招聘账户。
