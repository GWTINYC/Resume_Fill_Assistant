# Jev Apply · 网申助手（0.2 原型）

Chrome / Edge 浏览器扩展：本地保存个人资料，识别网申字段，预览确认后填入当前页面。使用 Manifest V3；建议使用最新稳定版浏览器，最低声明版本为 Chromium 140。

[下载最新版插件](https://github.com/GWTINYC/Resume_Fill_Assistant/releases/latest/download/jev-apply-extension.zip) · [版本发布记录](https://github.com/GWTINYC/Resume_Fill_Assistant/releases)

## 安装

1. 解压 `jev-apply-extension.zip`，保留整个文件夹。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 打开“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择包含 `manifest.json` 的 `jev-apply` 文件夹。
5. 在浏览器工具栏固定“Jev Apply · 网申助手”。

这是本地加载原型，尚未上架应用商店。Chrome 和 Edge 使用同一份扩展文件，但两边保存的资料相互独立。

## 使用

1. 打开一个普通网页，点击扩展图标，在侧栏选择“编辑资料 / 导入 PDF”。
2. 导入 PDF。PDF 解析在本机进行，支持有文本层的文件，最大 20 MB、40 页。自动找出邮箱和中国大陆手机号，供你核对；其余信息可对照提取文本填写。
3. 补充基本信息、教育经历、工作/实习经历、自定义资料及零散备注。经历按最新优先排列，点击“保存个人资料”。
4. 在网申页面点击扩展图标，选择“扫描当前页”。精确名称匹配无需 API key。
5. 如需智能识别，在“连接 Jev”中输入自己的 TypeSafe API key，点击“保存到本机”，再点击“Jev 智能匹配”。
6. 逐项核对资料映射、待填值和勾选状态。低置信度匹配保留空白，可以手动选择资料项。
7. 点击“填入勾选项”。已有内容默认跳过；只有明确勾选允许覆盖时才覆盖。
8. 自行检查网站校验提示、附件和条款，再点击网站的下一步或提交。换页后重新扫描。

API key 保存到扩展本地存储，重启浏览器后仍可使用，可替换或清除；不会写入分发的扩展包或资料 JSON。PDF 原文件、文件名、保存时间和提取文本存于扩展自己的 IndexedDB，导入后自动保存，支持查看、下载原件、替换和删除。个人资料、自定义项与零散备注随“保存个人资料”持久保存，可导出/导入 JSON；PDF 单独下载备份。Chrome 与 Edge 的本地数据相互独立，不做云同步。

更新插件时，请覆盖原来的扩展文件夹，在扩展管理页点击“重新加载”，保留原路径与扩展身份。不要卸载后重装来更新；卸载扩展、清除浏览器配置或改变扩展身份可能导致本地数据丢失。旧版临时密钥若更新时已被浏览器清除，需要重新输入一次。

## 支持范围

- 标准 HTML 文本、邮箱、电话、数字输入框和 textarea。
- 标准 select 单选下拉框与 radio 单选组。
- 原生 date / month 日期控件；仅有年月时不会补造日期。
- 使用 label、aria-label、aria-labelledby、placeholder、name 及邻近标题识别字段。
- 同源、权限允许的 iframe；每个框架最多扫描 100 项。
- 为原生控件赋值后发送 input/change 事件，便于网站监听；具体框架仍需实站验证。
- 页面地址改变、元素失效、标签变化或资料更新时要求重新扫描。
- 本地规则匹配、Jev 字段映射、必要时的选项语义匹配，以及人工更正。

## 目前需要手动处理

- 北森、Moka、Workday 等站点尚未做专门适配，不能承诺所有页面直接可用。
- 自制下拉框、搜索选择器、级联地区、非原生日期控件、多选 checkbox、Shadow DOM、不可访问的跨域 iframe。
- 网站中“新增教育经历 / 工作经历”的按钮：先手动添加足够区块，再扫描。重复区块对应不清楚时需人工选资料项。
- 附件上传、验证码、同意条款、电子签名，以及下一步和提交。
- 图片扫描版 PDF、复杂排版、加密 PDF。首版不含 OCR，也不自动完整解析任意简历到结构化经历。
- 字段存在但未进入视口布局、隐藏在未展开选项卡、只读或禁用时，不会强制填写。

Jev 不负责生成任意字段值：它从已填写的资料项目或网页候选选项中选择。需要新的自我介绍、开放问答等内容时，请先自行准备并添加为自定义资料。

## 数据如何流动

1. **导入 PDF、编辑资料、扫描、精确名称匹配：本地。** PDF 原文件与提取文本存入本地 IndexedDB，重启浏览器后恢复；零散备注保存在本地，不会发送给 Jev。
2. **点击 Jev 智能匹配：** 向 `https://api.typesafe.ai/v1/systemone` 发送页面字段标签、类型、邻近标题、选项文字，以及资料“项目名称”。字段映射请求不发送保存的姓名、手机号等资料值。
3. **选项语义匹配：** 若“本科”与网页“Bachelor”等值无法精确匹配，额外发送该字段相关的单项资料值与候选选项。
4. **点击填入：** 选中的资料值写入当前网页。网页自身可能在输入时自动保存，插件不能控制目标网站的处理方式。

扩展没有自己的服务器、遥测或云同步；TypeSafe API 的数据处理适用其官方政策。扩展本地存储没有额外加密，不应当作密码保险箱。

权限仅包括 activeTab、scripting、storage、sidePanel，以及 TypeSafe API 域名。没有申请读取全部网站的常驻权限。

## 匹配原则

固定模型 `jev-1.13.0`，每批最多 6 个问题。采用 `choice`，含 none 候选项。只有 choice 在预定义候选中，且选中概率和 confidence 均至少为 0.80，才接受自动建议。这是首版经验门槛，不代表 80% 的正确率保证；需要真实网站和资料上的验证。

模型返回的是资料项或选项的 ID，不执行模型生成的脚本或网页操作。页面中的文字被视为待判断数据。所有建议先展示，实际填写由用户点击触发。

## 测试范围

- 8 项核心测试：个人资料值不进入字段映射请求、重复经历不擅自选第一条、字段类型边界、日期不补造、候选项限制、概率门槛等。
- Chrome for Testing 的 MV3 扩展端到端测试：PDF 读取、资料保存、扫描、匹配、预览、填入、input/change 事件、默认跳过已有内容、不操作文件/条款/提交、过期页面拒绝、无效日期回滚、同源 iframe。
- Microsoft Edge 的同类端到端测试。
- 真实 TypeSafe API 联调通过，使用虚构个人信息与演示网页。常规自动测试使用模拟 API，以避免持续计费。
- 浏览器自动测试仅在临时测试副本中添加 localhost 权限，以代替人工点击工具栏触发 activeTab；交付扩展没有 localhost 或全站常驻权限。
- 正式 Chrome 的命令行加载扩展受浏览器限制，尚未通过其正常界面手动加载验证；上述 Chrome 测试运行于 Chrome for Testing。
- 0.2 增加整浏览器关闭/重启的回归测试：确认 API key、原始 PDF、提取文本、个人资料、零散备注可恢复；下载的 PDF 与原文件逐字节相同，并验证替换、删除、备注导出及旧版会话密钥迁移。
- 还未使用用户的实际 PDF、真实网申账户或目标企业网站验收。

## 开发

源码包需要 Node.js 与 npm：

```sh
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:browser
```

构建产物位于 `dist/`。安装 Microsoft Edge 后可运行 `BROWSER_CHANNEL=msedge npm run test:browser`。真实服务联调可通过环境变量 `TYPESAFE_API_KEY` 启用，测试只提交虚构数据。

主要文件：

- `src/core.js`：资料定义、映射与请求结构。
- `src/page.js`：网页扫描和受约束的填写。
- `src/background.js`：脚本注入与官方 API 请求。
- `src/panel.js`：扫描、匹配、预览、确认填写。
- `src/options.js`：个人资料、零散备注编辑与 PDF 本地管理。
- `src/storage.js`：本地密钥持久化与 IndexedDB 文件存储。
- `tests/`：核心及浏览器测试。

PDF 解析使用 Mozilla PDF.js，许可证见 `vendor/PDFJS-LICENSE`；构建时随包分发所需的字体、字符映射与 worker，不使用远程脚本。
